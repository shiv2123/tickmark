# Contributing

## Branching

`main` is protected: no direct pushes, PR required, CI must pass.

Work happens on short-lived branches:

```
feat/<slug>     new capability
fix/<slug>      bug fix
test/<slug>     tests only
docs/<slug>     documentation only
refactor/<slug> no behaviour change
eval/<slug>     eval harness, corpus, or protocol
```

One branch per unit of work. If a branch has been open for more than two sessions, it is too big.

## Commits

Conventional commits. The type prefix is not decoration; it is what generates the changelog.

```
feat(engine): add stale-approval check to CM-2
fix(scope): exempt revert PRs from CM-3
test(cm2): cover co-authored approver case
docs(adr): record three-valued logic decision
eval(corpus): freeze stratum A at 80 PRs
refactor(collect): split evidence normalization out of the client
```

Rules:

- Present tense, imperative. "add", not "added".
- The body explains **why**, not what. The diff already says what.
- Reference the issue: `Closes #14`.
- Commit when something works, not on a timer. A commit should be a state you would be willing to
  branch from.

## Pull requests

Every PR, including your own, gets a description that answers three questions:

1. What changed?
2. Why this approach rather than the obvious alternative?
3. How was it verified?

Self-merge is fine on a solo project. Skipping the description is not — the PR record is the change
record, and this project is about change records.

## Tests

- Deterministic assertions require fixture-based unit tests, including the tricky cases documented in
  ADR 0004.
- A bug fix requires a test that fails before the fix.
- `make test` must pass before merge. CI enforces it.

## Evaluation

The eval protocol in `eval/PROTOCOL.md` is binding once committed. In particular:

- The held-out set is touched exactly twice, and both runs are published.
- Corpus changes after freeze go into a new disclosed version, never into the frozen set.
- Labels are never generated by a model. See ADR 0004.

If a change would alter a published number, it must be re-measured and the README updated in the same
PR.

## Releases

Semantic versioning. `CHANGELOG.md` is updated in the release PR, not retroactively. Tag on merge to
`main`.
